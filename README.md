## What is here

| Folder | Contents | Public? |
|---|---|---|
| `docs/` | The published website — landing page plus one HTML page per lecture | **Yes, world-readable** |
| `lectures/` | LaTeX source for every lecture **and** the graded problem sets | No |
| `scripts/` | Narration scripts for the lecture videos, one file per lecture | No |
| `figures/` | Source SVG figures, generated by `tools/make_figures.py` | No |
| `canvas/` | QTI and Moodle XML packages for importing exercises into Canvas | No |
| `tools/` | The build pipeline (see below) | No |
| `patches/` | Idempotent recovery scripts for past source revisions | No |

> **Important.** A GitHub Pages site is public even when its source
> repository is private. Everything in `docs/` is visible to anyone with
> the URL, including students. The graded problem sets and the Canvas
> packages are deliberately kept **out** of `docs/` — `tools/build_site.py`
> never copies them there. Do not add them by hand.

## The pipeline

Each lecture is one LaTeX file, and it is the single source of truth.
From it the tools generate the interactive web page, the Canvas exercise
package, and (via the narration scripts) the video.

```
lectures/lecNN-*.tex
        │
        ├── tools/build_html.py  → one self-contained interactive HTML page
        ├── tools/build_site.py  → the whole docs/ website
        ├── tools/export_lms.py  → canvas/*.zip  (QTI 1.2) and *.xml (Moodle)
        └── tools/make_figures.py → figures/*.svg
```

### Rebuilding the website

```sh
python3 tools/build_site.py
```

This regenerates everything under `docs/`. Commit the result and GitHub
Pages republishes automatically.

### Rebuilding one page for local inspection

```sh
python3 tools/build_html.py lectures/lec01-linear-systems.tex build/lec01.html
```

Pages built this way inline the math font, so a single `.html` file works
offline and can be emailed. The website build instead links the font once
from `docs/fonts/`, which keeps each page around 130 KB instead of 1.1 MB.

### Rebuilding the Canvas packages

```sh
python3 tools/export_lms.py lectures/lec01-problemset.tex canvas/lec01-problemset
```

### Checking a build before publishing

```sh
python3 tools/verify_demo.py
```

Drives a headless browser over every page and fails if a knowl does not
open, a proof does not expand, an exercise grades wrongly, a figure is
missing, a formula overflows its column, or any JavaScript error occurs.
Run it before every commit that touches `docs/`.

## Source conventions

- `\lecture{N}{Title}` opens each file, followed by `\author{}` and
  `\institution{}`, which become the byline on the page.
- Statement environments: `definition`, `lemma`, `proposition`,
  `theorem`, `corollary`, `example`, `remark`, `intuition`. Each is
  numbered `N.k` in source order.
- `\kref{label}{link text}` is a cross-reference. Within a lecture it
  unfolds the target in place; across lectures it becomes a link marked
  with `↗`.
- `\begin{amatrix}` is an augmented matrix: a `pmatrix` with a vertical
  rule before the last column.
- `\incfig{name}{caption}` inlines `figures/name.svg`.
- Exercises are `\begin{exercise}[type=numeric|multichoice|proof]` with
  `\answer{}`, `\choice{}` / `\choice*{}` for the correct option,
  optional `\tolerance{}`, and optional `\hint{}`.
